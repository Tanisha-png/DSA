    How every solution is built

    A problem is dynamic programming when you make a series of choices, the same smaller question keeps coming up along different routes, and the best answer is built from the best answers to those smaller questions.

    It is 2D when you need two numbers to say where you are:

    StateWhat the two numbers meanFamily
    dp(i, j)I am at row i, column jGrid paths, squares
    dp(i, j)I have used s1 up to i and s2 up to jTwo strings
    dp(i, j)I am looking at the slice from i to jIntervals
    dp(i, c)I am at item i with c capacity leftKnapsack
    dp(i, s)I am on day i and in mode sIndex + state

    A good test: what is the least I need to know about where I am, so that I can finish the problem without caring how I got here? If the answer is two numbers, you are in the right place.

    Four versions of the same solution

    version 1Plain recursionCorrect but very slow. Write it first to get the logic right.
    version 2MemoSame code plus a table that remembers answers. Two extra lines.
    version 3Table (bottom-up)Fill the table with loops. No recursion, so no stack overflow.
    version 4One rowKeep only the rows you still need. Same speed, much less memory.

    In the code boxes, the lines that memoization adds have a yellow bar. Switch to the Recursion tab to see the same code with those lines removed.

    Two ways to read a state

    Most notes never say this out loud, but it causes a lot of confusion. dp(i, j) can mean the answer for the rest of the problem starting at (i, j), or the answer for a piece that ends exactly at (i, j). Both work for most problems. Which one you choose decides the loop direction.

    This handbook uses "from here to the end" for grids, strings, knapsack and stocks, so you only have one habit to learn. Squares use "ending here", because a square is easiest to describe by its bottom-right corner. The Dungeon Game (A6) only works "from here to the end", and you will see why.

    Padding is the base case

    When you turn a memo into a table, add one extra row and column filled with the base-case value. Then the loops need no "am I outside the grid?" checks. In the steppers, padding cells have a dashed grey border. They are filled before the first step.

    Loop direction rule: if dp(i, j) reads row i + 1, loop i downward. If it reads i − 1, loop upward.

    Explaining it in an interview

    1. "Let dp(i, j) be [the state in plain words]."
    2. "From here I can [choices], so dp(i, j) = [recurrence]."
    3. "It stops when [base cases]."
    4. "The answer is [answer state]."
    5. "There are [number of states] states and each does [number of choices] work, so the time is [product]."
    6. "I would write it top-down first, then turn it into a table and keep only [one or two rows]."
